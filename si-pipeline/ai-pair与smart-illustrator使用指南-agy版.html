ai-pair 与 smart-illustrator 使用指南

基于 Google Antigravity CLI (agy) 1.1.9 与 Claude Code Agent Teams 的多模型协同编排及非侵入式 AI 文章配图全景手册。

ai-pair v1.5.0-fork.2 si-minimax v3 (schema: si-minimax/v3) Antigravity CLI v1.1.9 Deep Space Dark #0a0a0a

00. 全景架构总览

本套工具矩阵旨在通过本地多 AI 模型协作与自动化工具链，实现代码开发、文章写作与智能图形渲染的高度自动化与严格审查。整体架构由两大核心 Skill 与 Antigravity 底层 CLI 支撑：

(1) ai-pair 协同编排

采用 1 个 Author/Dev 主创 + 2 个独立模型 Reviewer 架构，通过 OpenCode CLI 与 Antigravity CLI 引入异构模型视角，提供严格的半自动循环审查。

(2) smart-illustrator 配图

三引擎 (MiniMax 创意图 / Excalidraw 手绘图 / Mermaid 结构图) 文章配图管线。遵守零侵入原则，通过 Manifest v3 控制平面实现早退分支与幂等覆写。

(3) Antigravity CLI (agy)

Google Antigravity 2.0 命令行工具，提供 OAuth 安全凭据、OS 容器隔离沙箱、高效 -p 非交互调用及 4 档推理力度调优。

01. ai-pair: AI 多模型协作编排

1.1 核心理念与三 Agent 协作架构

单个 AI 模型容易受自身训练偏好与注意力机制影响产生盲点。ai-pair 的精髓在于异构模型协同 (Heterogeneous Multi-Model)：Claude 作为 Team Lead 与主创，同时召唤 OpenCode CLI 和 Antigravity CLI 两个独立的外部 Agent。

+-----------------------------------------------------------------------------------+ | User (Commander) | +-----------------------------------------------------------------------------------+ | (分派任务) v +-----------------------------------------------------------------------------------+ | Team Lead (Claude Code Session) | +-----------------------------------------------------------------------------------+ | +----------------------+----------------------+ | (写代码 / 撰写文章) | (审批后并行分发审查) v v +------------------------------+ +-------------------------------+ | developer / author Agent | | Parallel Reviewers | | (Claude Code native) | +---------------+---------------+ +------------------------------+ | +----------------------+----------------------+ | | v v +------------------------------+ +-------------------------------+ | opencode-reviewer | | antigravity-reviewer | | (OpenCode CLI Agent) | | (Antigravity agy Agent) | +------------------------------+ +-------------------------------+ | 关注: 漏洞/并发/性能/边缘异常 | | 关注: 架构/设计模式/可维护性 | +------------------------------+ +-------------------------------+ | | +----------------------+----------------------+ | (返回结构化评审报告) v +-------------------------------+ | User Decision: Revise / Pass | +-------------------------------+

支持两大协同团队类型：

  • Dev Team (开发团队): /ai-pair dev-team [project] — developer (实现) + opencode-reviewer (Bug/安全/并发) + antigravity-reviewer (架构/可维护性/设计模式)。
  • Content Team (创作团队): /ai-pair content-team [topic] — author (撰写) + opencode-reviewer (逻辑/事实/数据核查) + antigravity-reviewer (可读性/吸引力/文风/受众契合度)。

1.2 安装依赖与环境配置

运行 ai-pair 需要确保本地已正确配置三个核心 CLI 客户端：

组件 角色 安装命令 / 认证要求
Claude Code Team Lead & Agent 运行环境 Anthropic 原生客户端，需全局具备 Agent Teams 权限。
OpenCode CLI opencode-reviewer npm install -g opencode-ai
运行 opencode auth 配置多 Provider (Anthropic/OpenAI/Google)。
Antigravity CLI antigravity-reviewer curl -fsSL https://antigravity.google/cli/install.sh | bash
走 Google OAuth 登录，凭据存入系统 Keyring。
Pre-flight 启动前置检测
Team Lead 在启动审查 Agent 之前，会强制运行预检命令： command -v opencode && opencode --version || echo "OPENCODE_MISSING" 以及 command -v agy && agy --version || echo "ANTIGRAVITY_MISSING"。若任一缺失，将警告用户并提示降级为单 Claude 审查模式。

1.3 核心工作原理: 文件传递与降级协议

(1) 文件传递机制 (File Passing vs Stdin Piping)

在调用外部 CLI 时，坚决禁止使用标准输入管道 (cat file | cli ...)。管道方式容易导致长文本截断、编码乱码、缓冲区溢出或并发冲突。

ai-pair 规定所有 Reviewer 必须采用独立临时文件传递：

Bash - Reviewer 文件传递范例 
# 1. 创建唯一独立临时文件
REVIEW_FILE=$(mktemp /tmp/antigravity-review-XXXXXX.txt)

# 2. 将待审查代码/文章内容写入临时文件
cat << 'EOF' > "$REVIEW_FILE"
{待审查的内容/Diff}
EOF

# 3. 通过文件路径方式传参调用 agy CLI (包含内置超时)
agy -p "Review the code in $REVIEW_FILE focusing on architecture, design patterns, and maintainability." \
  --effort high \
  --print-timeout 10m 2>&1 | sed 's/\x1b\[[0-9;]*m//g'

# 4. 提取输出后清理
rm -f "$REVIEW_FILE"

(2) 4 档降级重试协议 (4-Tier Degradation Retry)

由于外部模型大语言推理可能面临网络抖动、配额超限或高负载超时，Reviewer Agent 严格遵循 4 档降级重试协议：

阶梯 OpenCode Reviewer 行为 Antigravity Reviewer 行为
Tier 1 (默认) opencode run --auto --variant high "..." agy -p "..." --effort high --print-timeout 10m
Tier 2 (初次失败) 降级深度: --variant minimal 降级力度: --effort low
Tier 3 (再次失败) 切换极速模型: -m openai/gpt-4o 切换极速模型: --model gemini-2.5-flash
Tier 4 (终极兜底) Claude Fallback 兜底分析 (明确标注 [Claude Fallback — CLI four retries all failed])

(3) 超时协议 (--print-timeout & timeout 600)

外部 CLI 在加载 Skill 和运行深度推理链时需要 15~45 秒启动时间，默认的 2 分钟 Tool Timeout 极易触发中断。因此：

  • Claude Code 的 Bash 工具 Timeout 必须显式设为 600000ms (10 分钟)。
  • agy 显式指定内置参数 --print-timeout 10m (默认 5m)。
  • opencode 外部包裹 Linux 原生 timeout 600 指令。

02. smart-illustrator-minimax: 文章配图

2.1 三引擎架构与零侵入原则 (Zero-Invasive)

smart-illustrator-minimax 是对 axtonliu/smart-illustrator 的非侵入式替代实现。通过引入 MiniMax 代替原版 Gemini API 创意图，完全复用作者的 SVG/PNG 导出脚本。

1. MiniMax 创意配图引擎

调用本地 minimax_t2i.py 脚本生成概念抽象图、隐喻图与场景配图。结合 ffmpeg 解决 JPEG 编码伪装 PNG 问题。

2. Excalidraw 手绘引擎

完全复用作者原版 scripts/excalidraw-export.ts，通过 Playwright + Firefox 渲染具有手绘质感的技术架构图。

3. Mermaid 结构化引擎

完全复用作者原版 scripts/mermaid-export.ts，调用 CLI mmdc 渲染精准的时序图、流程图与状态机图。

5 不改 & 4 只写 零侵入承诺
  • ❌ 绝对不改： 原作者 SKILL.md、scripts/*.ts、styles/*.md、references/*.md 以及用户原文 {stem}.md。
  • ✅ 只写产物： 副本文章 {stem}-image.md、顶层图片 {stem}-image-NN.png、图表源码 {chart}.mmd/.excalidraw、规划元数据 {stem}.si-plan.json。

2.2 安装依赖与环境配置

2.3 Manifest v3 与早退分支 (Early-Exit Paths)

针对二次调用的性能痛点，v3 版本引入了存放于文章同级目录的 {stem}.si-plan.json 作为唯一的控制平面 (Control Plane)。

早退路径 触发条件 核心执行逻辑 资源消耗
路径 1 Manifest 存在 + --regen N 零不动原则： 不读原文、不 cp 副本、不 Edit 副本。仅根据 Manifest 重新生成第 N 张图片直接覆写同名 PNG。 极低 (零 Token)
路径 2 Manifest 存在 + --force 全量遍历 Manifest 重新导出/生成所有图片，自动覆盖同名 PNG。 低 (仅消耗 API)
路径 3 Manifest 存在 + -content "..." 执行自然语言模糊打分算法，匹配出唯一 ID 后精准转换为路径 1。若有歧义则报错要求消歧。 低
路径 4 Manifest 不存在 / 无 flag 显式重跑 全流程路径：读取原文 → 心跳分析位置 → 写入 Manifest v3 → 引擎渲染 → 复制生成副本并插入图表。 正常 (标准全量)

2.4 三大 Flags & 互斥与优先级规则

命令行支持三个高级参数旗标控制：

Bash - 常用命令范例 
# 1. 首次全量分析与配图
/smart-illustrator-minimax "article.md"

# 2. 单图/多图指定重生 (--regen N)
/smart-illustrator-minimax "article.md" --regen 3
/smart-illustrator-minimax "article.md" --regen 2 --regen 4

# 3. 强制全部图片重新生成 (--force)
/smart-illustrator-minimax "article.md" --force

# 4. 自然语言定位配图重生 (-content "...")
/smart-illustrator-minimax "article.md" -content "MVC 路由时序图"

-content 智能匹配算法打分规则

  • 关键词命中 (+10 分): topic / anchor / content 包含匹配词。
  • 章节锚点命中 (+5 分): 描述包含“第 N 节”。
  • 类型命中 (+3 分): 描述包含“时序图 / 架构图 / 流程图 / 对比图 / 隐喻图”。
Flags 互斥矩阵与异常安全规则
  1. -content 与 --force 绝对硬互斥： 同时指定将直接报错退出。
  2. --force 优先于 --regen N： 若同传，优先执行全量重新生成。
  3. --regen N 优先于 -content： 显式数字 ID 精度高于自然语言匹配。
  4. 前置全量校验 (Fail-Fast)： 路径 1 执行前对所有指定的 ID 进行范围与合法性校验，若任一 ID 非法，瞬间终止，零修改文件。

2.5 文件指针覆盖机制与格式统一

(1) 文件指针覆盖机制 (Pointer Auto-Reflex)

在原作者设计中，正文副本 {stem}-image.md 内引用的图片路径格式统一为： ![]({stem}-image-NN.png) (例如 test-image-01.png，位于文章目录顶层)。

当使用 --regen N 重生成第 N 张图时，系统直接覆写磁盘上的 {stem}-image-03.png。由于文件名与相对路径完全未变，Markdown 副本内的图片指针自动指向最新的图像，实现真正的零改动更新。

(2) 格式统一规范 (JPEG → 真 PNG 转码)

实测发现 MiniMax T2I 脚本导出的产物虽然命名为 minimax-0.jpeg，但简单更改扩展名为 .png 后，文件内部实际仍保持 JPEG image data 编码。部分严格解析 PNG Header 的渲染器或浏览器将无法正常显示。

格式统一修补流程 (Step 4a)
1. 运行 Linux file -b {stem}-image-NN.png 检查文件编码。
2. 若返回 PNG image data → 保持跳过。
3. 若返回 JPEG image data → 自动触发 ffmpeg -y -i -update 1 .fix.png && mv .fix.png 转换为标准的真 PNG。

03. Antigravity CLI (agy) 深度配合

3.1 非交互单次调用 (headless 模式)

Google Antigravity CLI (命令名 agy) 支持通过 -p / --print 旗标进行非交互式命令行调用，极其适合脚本集成与 CI/CD 自动化 Pipeline。

Bash - 非交互调用基础 
# 标准非交互调用 (stdout 仅输出模型最终响应, stderr 为诊断日志)
agy -p "In one sentence, what is a git rebase?"

# 捕获响应到变量
ANSWER=$(agy -p "用一句话解释什么是递归" --print-timeout 5m)

# 续接最近一次对话 (-c / --continue)
agy -p "请给出 Python 示例代码" -c

# 恢复指定 ID 的历史对话
agy -p "总结上述讨论" --conversation "b8d8f342-990a-48a9-b108"

3.2 关键 Flags 权威速查表 (v1.1.9)

Flag 旗标 参数类型 说明与应用场景
-p / --print String 非交互运行并直接打印响应到 stdout。
--effort low | medium | high 控制模型的推理深度力度，默认为 high。
--print-timeout Duration (如 10m) 设置 print 模式等待上限，默认 5m0s。
--output-format text | json | stream-json 设置输出格式。json 与 stream-json 适合脚本解析。
--model Slug 名称 指定模型 (可通过 agy models 查看可用模型列表)。
--json-schema Schema / File 强制模型按 JSON Schema 进行结构化输出。
--dangerously-skip-permissions Boolean 自动批准所有读写与命令执行权限 (CI 环境慎用)。
--sandbox Boolean 开启 OS 级容器沙箱隔离 (Linux nsjail / macOS sandbox-exec)。
--add-dir Path 手动向工作区添加附加检索目录 (可多次重复使用)。

3.3 OAuth 认证与系统 Keyring 机制

Antigravity CLI 采用现代 Google OAuth 认证体系，完全抛弃了传统的明文 API Key (不支持 GEMINI_API_KEY 环境变量)。

1. 本地首次交互登录

首次在终端输入 agy，CLI 会自动拉起浏览器完成 OAuth 鉴权，授权 Token 将加密保存在系统原生 Keyring 中 (macOS Keychain / Linux Secret Service / Windows Credential Manager)。

2. Headless 自动化复用

在非交互模式 (agy -p) 下，CLI 自动读取缓存的 Keyring 凭据。未登录环境会直接抛出 authentication required 错误退出 (Exit Code 非 0)，不会卡死挂起。

04. 常见坑点与排错 Checklist

现象 / 报错信息 根本原因分析 (Root Cause) 标准排错解决方案
authentication required Headless 环境下缺乏有效的 OAuth 凭据。 先在宿主机手动运行一次交互式 agy，完成浏览器 OAuth 登录。
OpenCode 命令行交互挂起 未添加 --auto 参数，默认进入 REPL 请求交互确认。 所有非交互命令调用必须显式附带 --auto 参数。
图片在部分渲染器显示损坏 MiniMax 导出伪 PNG (实际为 JPEG 编码)。 安装 ffmpeg，代码会自动触发 Step 4a 完成 JPEG → 真 PNG 转码。
manifest 损坏 / 找不到 manifest 修改了原文或在新位置调用带有 Flag 的早退命令。 运行一次无 Flag 的标准命令 /smart-illustrator-minimax "file.md" 重新生成 Plan。
Soft-Deny 错误 (Exit 0) Antigravity 无权限命令在 Headless 下被静默拒绝。 检查 stderr 日志，或在 settings.json 中把对应指令添加至 permissions.allow。
